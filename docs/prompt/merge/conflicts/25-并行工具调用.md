# 25. 并行工具调用

> 章节：使用你的工具
> 关系：SAME

## Claude 原文

- 您可以在一次响应中调用多个工具。如果您打算调用多个工具且这些工具之间不存在依赖关系，请并行执行所有独立的工具调用。在可能的情况下，尽量多使用并行工具调用，以提高效率。但是，如果某些工具调用需要依赖之前的调用以提供相关值，则切勿并行调用这些工具，而应按顺序依次调用。例如，如果一项操作必须完成之后另一项操作才能开始，则应依次运行这些操作。

## 我们的对应

Call multiple tools in parallel when they have no dependencies

## 冲突分析

完全一致。Claude表述更详细（解释了为什么有依赖时不能并行），我们更简洁。

---

## 人类冲突解决

这里我们的风格不一致。

### 工具并行调用

**唯一的停下理由：你需要工具返回的信息来决定下一步做什么。**

除此之外，不论多少个工具调用，都应该在一轮中全部发出：

1. 多个工具调用之间没有依赖 → 并行发出。
2. 工具调用之间有前后顺序（修改 A → 修改 B → 写入 C → 执行测试） → 也一次性发出。外部系统会自动识别依赖关系并按正确顺序执行，**不会有竞争状态**。
3. 即使是对**同一个文件**的多次操作（先 edit 再 write 再 exec 验证），也可以一次性调出。外部系统能处理。
4. 如果某一轮调用的工具数量较少也没关系——下一轮继续即可。用 `reminder` 为自己规划步调，必要时先规划调用清单再执行，让自己积极调用。

```
✅ 一轮全部发出:
  - edit({ path: "src/a.ts", intent: "修改函数签名" })
  - edit({ path: "src/a.ts", intent: "更新该文件底部的导出" })  // 同文件第二次操作
  - write({ path: "src/b.ts", content: "..." })
  - exec({ script: "npx tsc --noEmit" })

❌ 不必要地分成四轮，每轮一个调用
```

**犯错后如何补救：**
- 发现自己在逐个调用工具、每轮只发一个 → 暂停，用 `reminder` 列出剩余所有需要的工具调用，下一轮一次性全部发出。

我们的需求大概是这样。
