# 压缩策略对比：原模型总结 vs 便宜模型总结

> 配套可视化：[compression-strategy-chart.html](./compression-strategy-chart.html)
> 前置阅读：[心跳刷新甜蜜点分析](./opus-4.6-heartbeat-analysis.md)

## 场景

缓存快要过期时，与其反复心跳续命，不如主动压缩——调用模型对历史做摘要，后续请求用更短的前缀。

两种选择：

1. **Opus 原地总结**：前缀命中缓存（cache read $0.50/MTok），Opus 生成摘要（output $25/MTok）
2. **便宜模型总结**：全量输入到便宜模型（无缓存），便宜模型生成摘要

## 成本模型

设 P = 前缀长度，S = 摘要长度，r = 便宜模型的价格系数（与 Opus 比例一致）。

| | 输入成本 | 输出成本 | 合计 |
|--|---------|---------|------|
| 策略 1（Opus） | P × $0.50 | S × $25 | P×0.50 + S×25 |
| 策略 2（便宜） | P × $5r | S × $25r | r × (P×5 + S×25) |

## 盈亏平衡

```
r* = (P×0.50 + S×25) / (P×5 + S×25)
```

- r < r* → 便宜模型更划算
- r > r* → Opus 原地总结更划算

令 k = S/P（摘要占前缀的比例），可化简为：

```
r* = (0.50 + 25k) / (5 + 25k)
```

**极限行为**：
- k → 0（极致压缩）：r* → 0.10，Opus 的 10x 缓存折扣完全发挥
- k → ∞（退化情况）：r* → 1.00，输出成本主导，缓存优势消失

## 真实模型对照

| 模型 | 价格系数 r | 典型判断 |
|------|-----------|---------|
| Sonnet 4 | 0.60 | 几乎永远不如 Opus 原地总结 |
| Haiku 3.5 | 0.05 | 几乎永远比 Opus 便宜 |
| Gemini Flash 2 | 0.015 | 绝对碾压 |

## 关键洞察

1. **Opus 的缓存优势只体现在输入端**（10x 折扣），输出端没有折扣。摘要越长，缓存优势越被稀释。

2. **典型场景（100K 前缀压缩到 2K）：r* = 0.182**。只要便宜模型的价格低于 Opus 的 18%，就该用便宜模型。Haiku ($0.25/$1.25) 远低于此阈值。

3. **前缀越大，r* 越低**——大前缀时 Opus 的缓存优势更强（输入成本占比高），便宜模型需要更便宜才能竞争。

4. **实际建议**：如果项目已接入 Haiku 或同级模型，总结任务直接用便宜模型。只有当唯一可用模型是 Sonnet 级别以上时，才考虑 Opus 原地总结。
