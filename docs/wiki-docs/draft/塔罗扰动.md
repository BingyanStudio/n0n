当 AI 认为自己完成了任务后，通过一次塔罗占卜引入随机扰动，让模型从牌面符号中自行解读出新的可能方向。

## 核心思路

AI 在优化过程中会收敛到局部最优并自行宣布"完成"。此时让它玩一次塔罗占卜——不是告诉它该怎么做，而是给它一组带有丰富先验含义的随机符号，让它自己建立映射。

模型本身对塔罗牌有充足的知识储备，每张牌的含义足够通用和模糊，怎么解释都能说通。这意味着：
- 不需要我们手动定义牌到任务的映射
- 扰动几乎不会产生纯噪音
- 模型在"解读"这个动作本身中就完成了视角转换

## 与随机鸡汤的区别

随机鸡汤是字面信息，模型会忽略。塔罗是一个需要主动完成的解读任务——它不是给答案，而是给符号，迫使模型自己去建立连接。仪式感和逐步揭牌的过程也很关键：一张张翻开、一张张解释，这个节奏本身就在引导模型做深度思考。

## Demo

`apps/tarot/` 实现了一个有状态的 CLI 占卜模拟器。模型通过 exec 工具逐步调用：

```
bun apps/tarot/src/index.ts focus "我的问题"   # 冥想问题
bun apps/tarot/src/index.ts draw 3              # 抽 3 张牌（面朝下）
bun apps/tarot/src/index.ts reveal              # 翻开第 1 张，看到牌面和牌意
bun apps/tarot/src/index.ts reveal              # 翻开第 2 张
bun apps/tarot/src/index.ts reveal              # 翻开第 3 张，显示完整牌面
```

每一步都是独立的 CLI 调用，状态持久化到 `.tarot-session.json`。牌库包含标准韦特塔罗 78 张牌，每张随机正逆位（共 156 种状态）。

## 触发

不需要自动检测"停滞"。最简单的触发方式：模型觉得自己做完了就去玩一把。由模型自行决定，或用户手动要求。

## 待验证

- 仪式感（逐步翻牌）相比一次性展示所有牌是否有差异
- 对不同类型的任务（开放式优化 vs 精确修 bug）效果是否有区别
