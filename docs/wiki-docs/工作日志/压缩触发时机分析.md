# 压缩触发时机分析

> 结论词条：【压缩策略】
> 配套可视化：[compression-trigger-chart.html](../../analysis/compression-trigger-chart.html)

## 场景参数

| 参数 | 值 |
|------|-----|
| 系统提示词 + 初始化 | 30K tokens |
| 每步输入 | 2K tokens |
| 每步输出 | 0.6K tokens |
| 每步增长 | 2.6K tokens |
| 压缩目标 | 5K tokens（历史部分）|
| 压缩后上下文 | 35K tokens（30K 系统 + 5K 历史）|
| 便宜模型价格系数 | r = 0.15 |

## 核心模型

假设会话足够长，需要周期性压缩。每 N 步压缩一次，优化目标是**平均每步成本最小**。

每个周期内：

- 上下文从 35K 线性增长到 (35 + N×2.6)K
- 每步的【提示词缓存】读取成本随上下文增长
- 周期末执行一次压缩（成本取决于【压缩策略】后端选择）

平均每步成本 = (周期内累计缓存读取 + 压缩成本) / N

## 结果

### 最优压缩间隔

| 策略 | 最优间隔 | 压缩时上下文 | 平均每步成本 |
|------|---------|-------------|-------------|
| Opus 原地 | 15 步 | ~74K | $0.0374 |
| Cheap (r=0.15) | 8 步 | ~56K | $0.0296 |
| 不压缩 | - | 持续增长 | 随步数线性增长 |

**全局最优：便宜模型每 8 步压缩一次**。

### 策略交叉点

r=0.15 时，当压缩时上下文超过 **425K**（约 150 步不压缩的积累量），Opus 原地压缩才比便宜模型划算。在最优周期性压缩方案中，上下文永远不会积累到这个量级。

### 50 步会话实例

| 方案 | 总成本 | 节省 |
|------|-------|------|
| 不压缩 | $2.34 | — |
| 最优 Cheap 压缩 | $1.46 | 37.7% |

## 洞察

1. 便宜模型在最优方案中全面胜出——最优间隔短（8 步，上下文仅 56K），远未到交叉点。
2. 压缩过早不划算——摊销的压缩成本太高。
3. 压缩过晚也不划算——上下文膨胀导致每步缓存读取贵。
4. 本质是 EOQ 问题——持有成本 vs 订货成本的平衡。

## 结论

已提取至【压缩策略】词条「触发时机」一节。
