Anthropic 的提示词缓存机制，允许在多次 API 请求间复用已处理的提示词前缀，避免重复计算。

## 工作原理

在请求中通过 `cache_control` 标记提示词前缀。首次请求触发 Cache Write（写入缓存），后续请求若前缀匹配则 Cache Read（命中缓存）。缓存有 5 分钟 TTL，每次命中自动刷新。

## 定价（Opus 4.6）

每个输入 token 按且仅按以下三种费率之一计价：

| 项目 | 价格 | 含义 |
|------|------|------|
| Input | $5 / MTok | 普通输入，不涉及缓存 |
| Cache Write | $6.25 / MTok | 首次写入缓存（含处理） |
| Cache Read | $0.50 / MTok | 命中已有缓存 |
| Output | $25 / MTok | 输出（与缓存无关） |

缓存命中时输入成本降低至 Cache Write 的 1/12.5。Cache Write 比普通 Input 贵 25%，但后续每次命中都按 Cache Read 计价，一次写入多次受益。

## 缓存失效成本

缓存过期后重新发送，前缀按 Cache Write 费率重新写入（$6.25/MTok），比 Cache Read（$0.50/MTok）贵 12.5 倍。

因此保持缓存存活（见【心跳策略】）和控制前缀增长（见【压缩策略】）对长会话成本控制至关重要。

## 跨模型比例一致性

Anthropic 各模型的 Cache Read / Cache Write 比例大致一致，【心跳策略】的盈亏平衡次数与模型选择关系不大。

| 模型 | Cache Read | Cache Write | Input |
|------|-----------|-------------|-------|
| Opus 4.6 | $0.50 | $6.25 | $5.00 |
| Sonnet 4 | $0.30 | $3.75 | $3.00 |
| Haiku 3.5 | $0.03 | $0.30 | $0.25 |
