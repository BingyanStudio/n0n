处理【批注】的操作流程。

## 1. 读取

扫描所有待处理【批注】，参见【批注】词条中的查询命令。

## 2. 概览与聚类

**先做全局分析，不要逐条零散修复：**

```
第一步：按文件分组 — 哪些文件有批注？
第二步：按类型聚类 — 批注属于哪类问题？
  - 【词条】定义修正 → 需要修改定义源头（遵循【SSOT】）
  - 【公式】修正 → 修改 %% 公式 %% 所在文件
  - 文案/措辞优化 → 直接修改对应行
  - 结构/逻辑调整 → 需要重组段落
第三步：识别【SSOT】关联 — 修改是否涉及被其他文档【引用】的词条？
```

## 3. 组织修复计划

```
修复计划：
├── 定义层修改（影响全局，优先处理）
│   ├── 修改词条文件 wiki-docs/暴击率.md
│   └── 修改公式 %% ... %% @ 文件Y:行号
├── 文件级修改（按文件聚合，一次性改完）
│   ├── 文件X：批注 #1, #3, #5（同文件合并处理）
│   └── 文件Y：批注 #2, #4
└── 验证：修改后检查引用该词条的其他文件是否受影响
```

**每个文件的修改应该一次性完成**，避免对同一文件多次零散编辑。

## 4. 更新状态

修复完成后，将对应【批注】标记为 `resolved`：

```bash
# 单条标记
jq --arg id "a1" '
  .annotations |= map(
    if .id == $id then .status = "resolved" | .updatedAt = (now | todate)
    else . end
  )
' annotation.json > tmp.json && mv tmp.json annotation.json

# 批量标记
jq --argjson ids '["a1","a3"]' '
  .annotations |= map(
    if .id | IN($ids[]) then .status = "resolved" | .updatedAt = (now | todate)
    else . end
  )
' annotation.json > tmp.json && mv tmp.json annotation.json
```
