## REMINDER

### 设计意图

模型在长线任务中容易忘记一开始的目标和整体的进展，常规解决方案有几种：

1. 在指定的时间点要求模型总结迄今为止的进展，并与最初的目标进行对齐检查。

2. 维护一个 todo list，记录当前的待办事项和已完成的事项，要求模型维护和更新这个 todo list。

reminder 是一个改良的方案，它模拟了类似人类工作，将规划、反思、规划融入模型的工作流程。最终目的是让模型在长线任务中保持对目标的清晰认识，并且能够在 规划 <-> 实际 的不一致间进行反思和调整。


### 工作流程

1. 模型自定义每个步骤的所需工作量（轮数），**承诺** 在 n 轮内完成这个步骤。
2. 若是模型在 n 轮内完成了这个步骤，则视为承诺达成，进入下一个步骤。
3. 若是模型在 n 轮内没有完成这个步骤，则视为承诺未达成，进入反思阶段。
4. 在反思阶段，模型需要分析为什么没有完成这个步骤，是什么原因导致的，并且提出改进措施。然后规划下一个步骤的工作量（轮数），并承诺在 n 轮内完成。
5. 重复上述流程，直到完成整个任务。


### 优势

1. 结合交替思考机制，（reminder会作为user消息插入），可以定期清空模型的思维过程，防止模型陷入思维陷阱。
2. 通过承诺机制，激励模型在每个步骤都保持对目标的清晰认识，并且能够在规划和实际执行之间进行反思和调整。
3. 通过定期的反思和调整，模型能够更好地理解任务的整体结构和目标，并且能够通过回顾，提升自己的工作效率。



### 现在状况

虽然已经实现了，但是现在仍然没有达到预期的效果，失效形式主要为：

1. 我们无法给模型提供**惩罚**，这导致模型无法在错误的时间评估中得到负反馈，无法形成有效的学习闭环。模型总是倾向于高估自己的能力，承诺在少量步骤中完成任务，但实际上无法做到。

2. 模型在反思阶段的分析和改进措施往往不够深入，甚至直接忽略了反思，而是继续推进下一个步骤。**承诺违背**是一件很严重的事情，因为它往往意味着：

- 模型可能错误的理解了任务
- 模型可能陷入了错误的解决方案
- 模型可能遭遇了意外的困难
- 模型可能需要外部的帮助
- 模型可能使用了非常低效的策略

对于每一种情况，都应该做出不同的反应和调整措施，而不是简单的继续推进下一个步骤。

- 应该重新理解任务，调整对任务的理解
- 应该重新评估解决方案，寻找更有效的解决方案
- 应该分析困难，寻找克服困难的方法，并且应该将其记录在案，以便未来参考
- 应该寻求外部帮助，寻找相关的资源和专家的建议
- 应该评估当前的策略，寻找更高效的策略，并且应该将其记录在案，以便未来参考
