# Fairy 设计决策

## 定位

一半角色扮演、一半工具使用的持久化 agent。
拥有记忆、设定、环境感知，可脱离用户指令自主行动。

## 核心决策

### 1. 状态驱动，而非对话驱动

传统 agent 依赖对话历史作为上下文，换窗口就丢失连续性。

fairy 的上下文从**全局状态重建**，而非线性堆叠对话：
- 每次对话从状态开始，每次回复更新状态
- 无论哪个窗口、哪个平台，都能保持连续性
- 没有用户指令时也能自主行动（因为本身不依赖指令）

### 2. 纯函数式状态转换

```
fairyRound(state, stimulus) → { response, newState }
```

所有输入（用户消息、定时触发、环境变化）对 fairy 都是等价的**刺激源**。
新触发自然打断旧触发——不存在"恢复中断对话"的问题。

### 3. 对话路径摘要 = reminder 提取

不需要额外的总结算法。从历史中只提取 reminder 调用和 user_input，
就得到天然的结构化摘要——reminder 本身就是 agent 对进度的记录。

### 4. 上下文前缀稳定性

上下文组装顺序按变化频率排列（身份→摘要→记忆→环境→刺激），
前缀越稳定，KV-cache 命中率越高。摘要使用跳变窗口进一步最大化缓存。

### 5. JSON + md，不用数据库

history.json 是 SSOT，identity.md/memory.md 是模型可直接 edit 的文件。
提供最好的可视化和可调试性，不需要数据库。
